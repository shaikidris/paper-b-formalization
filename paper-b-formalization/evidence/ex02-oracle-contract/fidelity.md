# EX0.2 interface fidelity

The paper's construction chooses one deterministic build and one query procedure. The candidate quantifies over both procedures and a uniform positive cost constant before taking an explicitly stored DAG and original source. It observes one build on that graph and source, then quantifies over every later original-ID failure set and target using the resulting flat immutable word array and header. No query parameter supplies the original adjacency. The concrete interpreter must establish that the fixed query program has access only to that payload and query.

The graph counts repeated arc occurrences, and the query compares its Boolean result to the original deletion-path predicate. Its failure type has zero, one and two slots. A path of length zero still checks the endpoint. The candidate stores width using the combined input size and requires separate bounds for build work, peak live words, retained words and later query work. The executable memory layout must justify address fit and account for temporary space and metadata.

The v1.3 type uses the square of the logarithmic scale for build time and its first power for query time. The pinned v1.2 type uses the cube in both places. The checked implication reuses the same programs, graph and build and query observations. These are typechecked contracts for EX0.2. EX0.3 and EX5 must instantiate the observer with genuine executions.

The exit-predicate type is checked on each real edge of the constructed forest of a supplied flat quotient. It quantifies the coordinate, target in the child proper-loss set and original physical tail. The graph-to-quotient transfer remains part of EX1 and EX3.
